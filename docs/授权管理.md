# 授权管理操作文档

面向软件的**发行方（你自己）**与**售后支持**，说明如何签发、交付、更换与排查授权。
用户只需要会一件事：在「设置 → 授权」里粘贴激活码。

---

## 1 这套授权是怎么工作的

| 角色 | 放在哪里 | 说明 |
| --- | --- | --- |
| 私钥 | 你的本机 `.license-private.pem` | 只用来签发授权码；泄露 = 谁都能签 |
| 公钥 | 随安装包发布 `server/license-public.pem` | 客户端用它验签；可以提交到仓库 |
| 授权码 | 发给用户的一串文本 | `TUKU1.<payload>.<signature>`，离线可验 |
| 机器码 | 用户软件里显示 | 由 4 项硬件特征算出，形如 `0E3F-5944-0D13-4C69` |
| 授权文件 | 用户数据目录 `data/license.key` | 激活成功后写入，跨资源库共用 |

三条原则：

1. **不联网**：验签是本地计算，断网可用，也不需要你维护服务器。
2. **绑定机器**：授权码里签了机器码，换到别的机器验不过。
3. **可容错**：4 项硬件里变 1 项仍算同一台，换硬盘 / 重装系统不用重签。

> 边界：授权码本身仍是离线验签；离职/违约的**远程停用**依赖一份由同一把私钥签名的停用清单（见第 6 节）。没有配置清单地址时，软件保持纯离线，不额外联网。

## 2 首次准备（只做一次）

### 2.1 生成密钥对

```bash
node scripts/license-keygen.mjs
```

- 公钥 → `server/license-public.pem`（**提交进仓库**，随安装包发布）
- 私钥 → `.license-private.pem`（已在 `.gitignore`，**绝不提交**）

当前仓库已经生成过一对密钥。脚本检测到公钥存在会拒绝覆盖。

### 2.2 备份私钥（必做）

把 `.license-private.pem` 的**全文**存进密码管理器，再存一份到离线 U 盘。

- 丢了：老用户不受影响，但你无法再为新机器签发。
- 泄露：立刻停止发货；已发布安装包里的公钥换不掉，只能靠换版本 + 新密钥重建授权体系。

### 2.3 确认私钥没有进仓库

```bash
git status --short
git ls-files | findstr license-private
```

第二条应当没有任何输出。

## 3 日常签发流程

### 3.1 向用户要机器码

用户打开「设置 → 授权」，复制「当前机器」那一行的机器码，例如：

```
0E3F-5944-0D13-4C69
```

带不带横线、大小写都无所谓，脚本会自动规范化。

### 3.2 签发

```bash
node scripts/license-issue.mjs --machine 0E3F-5944-0D13-4C69 --days 365 --account zhangsan --note buyer@example.com
```

- `--account` 会写进授权码，作为离职停用的匹配键；不填也能用，但只能按机器停用。
- `--note` 只是展示备注，通常是购买邮箱。

输出示例：

```
[license] 机器码： 0E3F-5944-0D13-4C69
[license] 有效期： 2026-12-20
[license] 激活码：
TUKU1.eyJ2IjoxLCJwcm9kdWN0IjoidHVrdSIs...
```

把最后一行（`TUKU1.` 开头）完整发给用户即可。

### 3.3 参数说明

| 参数 | 说明 | 默认 |
| --- | --- | --- |
| `--machine <码>` | 绑定机器码；必填，除非用 `--any` | 无 |
| `--days <N>` | 有效天数；`0` = 永久 | `365` |
| `--expires <YYYY-MM-DD>` | 指定到期日（优先于 `--days`） | 无 |
| `--note <文本>` | 备注，通常是购买邮箱；会显示在用户设置页 | 空 |
| `--edition <名称>` | 版本名，目前只有 `pro` | `pro` |
| `--any` | 不绑定机器（试用 / 内部测试） | 关 |
| `--out <路径>` | 同时把激活码写进文件，例如 `licenses/buyer-2026.key` | 不写 |

有效期规则：只写日期时按**当天 23:59:59** 失效，不会出现「买到当天上午就说过期」。

### 3.4 用户激活

用户在「设置 → 授权」粘贴激活码 → 点「激活」，立即生效，无需重启。

## 4 常见场景

| 场景 | 做法 |
| --- | --- |
| 年费续期 | 用同一机器码再签一张更晚到期的授权，让用户重新粘贴覆盖 |
| 换电脑 | 新机器码重新签一张；旧授权文件留在旧机器上，无需处理 |
| 用户重装系统 / 换硬盘 | 机器码 4 组里通常只变 1 组，原授权仍可用；变 2 组及以上再重签 |
| 试用 | `--any --days 14`，到期后专业版能力自动关闭 |
| 团队 / 内部 | `--any --days 0`，不绑定机器；**不要外发**，等同于万能钥匙 |
| 批量发货 | 一次一条命令，建议统一加 `--out licenses/<订单号>.key` 留档 |
| 退款 / 违约 | 离线无法吊销：停发新授权、只卖年费；必要时升级为带在线租约的方案 |

## 5 用户侧会看到什么

- **免费版**：全部基础功能可用（浏览、整理、搜索、堆叠、笔记、基础编辑与导出）。
- **专业版**：额外开放 3 项能力
  1. 局域网投送与只读分享（`/api/lan`）
  2. 插件脚本执行（`/api/plugins/:id/run`）
  3. AI 夜间批处理（`/api/night-batch`）
- 免费版点这些功能会收到明确提示：「需要专业版授权，请在『设置 → 授权』中激活」，不会静默失败。
- 授权卡片显示：版本、机器码、到期日、剩余天数、签发备注。
- 「取消授权」只删除本机授权文件，不影响用户手里的激活码，重新粘贴即可恢复。

## 6 故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 提示「激活码格式不正确」 | 复制不全、被邮件折行 | 让用户重新完整复制 `TUKU1.` 开头的整段 |
| 提示「签名无效」 | 激活码被改过 / 复制缺字符 | 重新发送原始激活码 |
| 提示「与当前机器不符」 | 换了机器，或 2 项以上硬件变化 | 让用户发新机器码，重新签发 |
| 提示「授权已过期」 | 到期 | 续期重签 |
| 激活成功但功能仍被挡 | 服务端进程未更新（老版本） | 升级到含授权模块的版本后重试 |
| 设置页显示「未内置授权公钥」 | 打包时漏了 `server/license-public.pem` | 检查打包产物，确认 `server/**/*` 被包含 |
| 修改硬件后机器码变了 | 正常 | 单组变化不影响；多组变化需重签 |

机器码由这些项各取 4 位组成：

1. Windows `MachineGuid`
2. CPU `ProcessorId`
3. 主板序列号
4. 系统盘 `C:` 卷序列号

读不到的项显示为 `0000`，不参与比对；可比较项少于 2 项时直接判定无法识别。

- [ ] `server/license-public.pem` 存在且随包发布
- [ ] `.license-private.pem` 不在 `git status` / `git ls-files` 里

- [ ] 在干净机器上跑一遍：免费版受控能力返回 402 → 激活 → 能力放行
- [ ] 用 `--machine` 签一张真授权，确认能在目标机器激活
- [ ] 确认没有把 `--any` 签发的通用授权误发出去

回归命令：

```bash

npm run lint
npm run unit
npm run smoke
```

`smoke` 已覆盖「免费版 402 → 有效激活 → 专业版放行」整条链路。

## 8 安全红线

1. **私钥不进仓库、不进聊天记录、不放 CI 明文**；CI 需要签发时用 secret 注入 `TUKU_LICENSE_PRIVATE_KEY`。
2. **已发布的公钥永远不要换**。老安装包只认旧钥匙，换公钥等于让老用户无法激活。
3. 热更包可以改 `server/` 下的 JS，但**不要**通过热更替换授权逻辑或公钥，否则会出现「同一个版本、两台机器行为不同」的排查噩梦。
4. 通用授权（`--any`）只用于试用与内部，发放记录单独留档。
5. 建议主推**年费**：离线方案没有吊销能力，永久授权一旦发出就无法收回。

## 9 技术附录

### 9.1 授权码结构

```
TUKU1.<base64url(payloadJson)>.<base64url(ed25519 签名)>
```

payload 字段：

```json
{
  "v": 1,
  "product": "tuku",
  "edition": "pro",
  "machine": "0E3F-5944-0D13-4C69",
  "issuedAt": "2026-11-20",
  "expires": "2026-12-20",
  "note": "buyer@example.com",
  "seats": 1
}
```

- `machine` 为空 = 不绑定机器。
- 签名覆盖 payload 的原始字节，任何字段改动都会验签失败。
- 也接受 `{"key":"TUKU1..."}` 形式的 JSON（用户存文件后粘贴时常见）。

### 9.2 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/license` | 当前状态；`?refresh=1` 重新探测硬件 |
| `POST` | `/api/license/activate` | body `{ "key": "TUKU1..." }` |
| `POST` | `/api/license/deactivate` | 删除本机授权文件 |

未授权时受控接口返回：

```json
{ "error": "「局域网投送与只读分享」需要专业版授权，请在「设置 → 授权」中激活", "code": "license_required", "feature": "lan" }
```

### 9.3 环境变量

| 变量 | 作用 |
| --- | --- |
| `TUKU_LICENSE_PUBLIC_KEY` | 覆盖内置公钥（CI / 测试用） |
| `TUKU_LICENSE_PRIVATE_KEY` | 签发脚本读取私钥（CI secret） |
| `TUKU_BUY_URL` | 设置页显示「购买专业版」按钮的地址 |

### 9.4 相关文件

| 路径 | 说明 |
| --- | --- |
| `server/lib/license-core.js` | 签发 / 验签 / 机器码纯逻辑 |
| `server/lib/license.js` | 硬件探测、授权文件、能力闸 |
| `server/routes/license.js` | 三个授权接口 |
| `scripts/license-keygen.mjs` | 生成密钥对 |
| `scripts/license-issue.mjs` | 签发授权码 |
| `web/src/pages/settings/LicenseCard.tsx` | 设置页授权卡片 |
| `test/license.test.mjs` | 授权单测 |

### 9.5 扩展一项专业版能力

1. 在 `server/lib/license-core.js` 的 `PRO_FEATURES` 加一项 `{ key, label }`。
2. 在 `server/app.js` 里给对应路由挂 `app.use('/api/xxx', requirePro('xxx'))`，或在单个路由上挂 `requirePro('xxx')`。
3. 设置页的授权卡片会自动列出这项能力（前端按 key 配文案的话，在 `LicenseCard.tsx` 的 `FEATURE_LABELS` 补一条）。
4. 在 `test/license.test.mjs` 与 `scripts/smoke.mjs` 补一条「免费 402 / 激活后 200」的断言。

## 10 远程停用（离职管理）

1. 签发时用 `--account` 绑定账号：

   ```bash
   node scripts/license-issue.mjs --machine 0E3F-5944-0D13-4C69 --account zhangsan --days 365
   ```

2. 生成签名的停用清单：

   ```bash
   node scripts/license-revoke.mjs --account zhangsan --seq 1 --out license-revoke.json
   ```

   - 也可以按机器停用：`--machine 0E3F-5944-0D13-4C69`
   - 可以同时传多个 `--account` / `--machine`
   - `--seq` 必须递增；客户端拒绝比本地缓存更旧的清单

3. 把 `license-revoke.json` 放到任意静态 HTTP(S) 地址，并在启动/构建时设置：

   ```bash
   TUKU_LICENSE_REVOKE_URL=https://example.com/license-revoke.json
   ```

4. 客户端启动、手动刷新授权时会拉取；验签通过后缓存到 `data/license-revoke.json`。
   - 命中账号或机器：数据接口全部 403（只放行 `/api/license`、诊断包与系统信息），界面显示「软件已停用」。
   - 断网：使用上次缓存，不阻断正常授权。
   - 不要把这个 URL 做成用户可在界面里改的设置，否则离职员工可以自己关掉停用检查。

> 停用清单和授权码共用同一把 Ed25519 公钥；私钥仍然只在发行方手里。
> 注意：完全离线且从未联网的机器无法收到停用清单，这是离线授权的固有边界。

## 11 安全打包与还原（调试用）

打包发布建议用：

```bash
npm run dist:secure
```

它会在打包前用 esbuild 对 `electron/` 与 `server/` 的所有 JS 做压缩/标识符混淆，打包完成后**自动还原**源码。

- 源码备份：`.obfuscate-backup/<时间戳>/`（不进安装包，已在 `.gitignore`）
- 打包被中断、源码停在混淆状态时：

  ```bash
  npm run obfuscate:restore
  ```

- 本地调 Bug 时跳过混淆：

  ```bash
  TUKU_SKIP_OBFUSCATE=1 npm run dist
  ```

> 客户端代码无法做到「绝对不可逆」。混淆能提高逆向成本，但不能替代服务端校验；授权、远程停用、Pro 能力闸都在服务端/本地授权层，不要只靠前端隐藏按钮。

## 12 一键诊断包

设置 → 关于软件 → **生成诊断包（ZIP）**。

zip 内包含：

- `meta.json`：系统版本、CPU/内存、Electron/Node、时区、路径
- `network.json`：网卡、代理环境变量、主机名
- `settings.json`：设置项（password/token/apiKey/secret 等已替换为 `***`）
- `license.json`：授权状态、账号、机器码、是否被停用（不含授权码原文）
- `oms.json`：OMS 配置状态（不含密码）
- `actions.json`：最近 200 条操作日志
- `client.json`：浏览器/渲染进程环境与当前页面
- `logs/`：最近的 `.log/.err`（token、Bearer、授权码已脱敏）
- `description.txt`：用户填写的问题描述/复现步骤

用户提交 Bug 时只需要发这个 zip。
