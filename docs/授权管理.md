# 授权管理操作文档

面向软件的**发行方（你自己）**与**售后支持**，说明如何签发、交付、更换与排查授权。
用户需要提供两样东西：**手机号 + 设备码**，收到激活码后在「设置 → 授权」里粘贴。

---

## 1 这套授权是怎么工作的

| 角色 | 放在哪里 | 说明 |
| --- | --- | --- |
| 私钥 | 你的本机 `.license-private.pem` | 只用来签发授权码；泄露 = 谁都能签 |
| 公钥 | 随安装包发布 `server/license-public.pem` | 客户端用它验签；可以提交到仓库 |
| 授权码 | 发给用户的一串文本 | `TUKU1.<payload>.<signature>`，离线可验 |
| 手机号 | 用户购买时提供 | 写进授权码，作为账号标识与远程停用匹配键 |
| 设备码 | 用户软件里显示 | 由 4 项硬件特征算出，形如 `0E3F-5944-0D13-4C69` |
| 授权文件 | 用户数据目录 `data/license.key` | 激活成功后写入，跨资源库共用 |

三条原则：

1. **不联网**：验签是本地计算，断网可用，也不需要你维护服务器。
2. **绑定手机号 + 设备码**：授权码里同时签了手机号和设备码，换机器验不过；远程停用按手机号或设备码匹配。
3. **可容错**：4 项硬件里变 1 项仍算同一台，换单件硬件 / 重装系统通常不用重签。

> 关系是**多对多**：一个手机号可以签多台设备；同一台设备也可以签给多个手机号（各拿一份激活码，本机同一时间只激活其中一份）。

> 边界：授权码本身仍是离线验签；离职/违约的**远程停用**依赖一份由同一把私钥签名的停用清单（见第 10 节）。没有配置清单地址时，软件保持纯离线，不额外联网。

## 2 首次准备（只做一次）

### 2.1 生成密钥对

```bash
node scripts/license-keygen.mjs
```

- 公钥 → `server/license-public.pem`（**提交进仓库**，随安装包发布）
- 私钥 → `.license-private.pem`（已在 `.gitignore`，**绝不提交**）

当前仓库已经生成过一对密钥。脚本检测到公钥存在会拒绝覆盖。

### 2.2 备份私钥（必做）

把 `.license-private.pem` 的**全文**存进密码管理器，再存一份到离线 U 盘。

- 丢了：老用户不受影响，但你无法再为新机器签发。
- 泄露：立刻停止发货；已发布安装包里的公钥换不掉，只能靠换版本 + 新密钥重建授权体系。

### 2.3 确认私钥没有进仓库

```bash
git status --short
git ls-files | findstr license-private
```

第二条应当没有任何输出。

## 3 日常签发流程

### 3.1 向用户要手机号 + 设备码

用户打开「设置 → 授权」，会看到两样信息：

- **手机号**：用户自己的手机号。
- **设备码**：形如 `TK2-D0C4-0D13-4FD5-0000-0E3F-A04D`，带不带横线、大小写都无所谓。

两个都要发过来，只发其中一个无法签发。

设备码（v2）由 6 组本机特征各取 SHA-256 的前 4 位拼成：

1. SMBIOS UUID（整机唯一标识）
2. 主板序列号 + BIOS 序列号
3. 启动盘（系统盘）物理序列号
4. TPM 背书密钥（有 TPM 且可读取时；否则跳过）
5. Windows `MachineGuid`
6. CPU `ProcessorId` / 型号 + 物理网卡 MAC

**会变化的情况**：更换主板、启动盘或网卡；重装 / 克隆系统（`MachineGuid` 变化）；虚拟机迁移；批量刷写硬件序列号。
读不到的项显示为 `0000`，不参与比对；6 组里允许变 2 组，并且必须至少命中 1 个强特征（UUID / 主板 / 启动盘 / TPM）。重装系统、换单块硬盘或网卡通常仍可用；换主板等主要硬件需要重新签发。设备码只在本机计算，不上传原始序列号。

> 旧版 16 位设备码（`XXXX-XXXX-XXXX-XXXX`）只用于校验已售旧授权，不再用于新签发。新授权码需要 1.5+ 客户端；旧授权码继续按旧规则验证，不受影响。

> 参考做法：微软 SMBIOS / CHID 文档建议用 System Information 的 UUID、Serial Number、Baseboard Product 等字段做设备识别；Windows 激活与商业软件通常采用「多组件哈希 + 容忍部分变更 + 在线激活 / 席位 / 定期校验」的组合。纯离线指纹只能提高克隆成本，不能绝对防住整机克隆或改代码，真正的强控制仍要靠在线激活与停用清单。

### 3.2 图形化管理工具（推荐）

**双击运行（推荐）**：`release-build/license-admin/TuKu-LicenseAdmin-<版本>.exe`。
打开后就是一个独立窗口，不需要命令行。首次运行如果找不到私钥，会弹窗让你选择 `.license-private.pem`，导入后保存在本机用户数据目录，之后双击即用。

重新打包这个工具：

```bash
npm run license:admin:dist
```

开发环境也可以直接启动：

```bash
npm run license:admin          # 浏览器版（本地网页）
npm run license:admin:app      # Electron 窗口版
```

管理页只监听本机，令牌每次启动随机生成：

- **签发 / 续期**：填手机号 + 一个或多个新版设备码（`TK2-` 开头，每行一个），选 30 天 / 90 天 / 1 年 / 2 年 / 永久 / 自定义到期日；同一手机号 + 同一设备码再次签发会覆盖旧码并更新有效期。
- **授权记录**：查看手机号、设备码、签发日、到期日、剩余天数、状态；支持搜索、复制激活码、删除台账。
- **导入旧激活码**：扫描数据目录下以前用命令行 `--out` 导出的 `.key` / `.txt`，把带手机号 + 设备码的记录补进台账；没有手机号的旧授权会跳过。
- **取消授权**：在记录上点「取消设备授权」，或对手机号点「停用手机号」（该手机号下所有设备一起锁定）；停用会自动重新生成签名停用清单并递增 `seq`。
- **停用清单**：页面直接显示清单文件路径、本机地址、签名内容，可复制 / 下载；还会显示发布文件 `docs/license/license-revoke.json` 和 Gitee 地址，点「写入发布文件」后只需 `git commit && git push`。

工具数据只保存在本机：

- 开发态：仓库下 `licenses/admin.json`、`licenses/license-revoke.json`
- 安装版：用户数据目录下的 `licenses/`（页面会显示完整路径）
- 台账含完整激活码，已在 `.gitignore`，**不要提交**

### 3.3 命令行签发（可选）

```bash
node scripts/license-issue.mjs --phone 13800000000 --machine TK2-D0C4-0D13-4FD5-0000-0E3F-A04D --days 365 --note buyer@example.com
```

- `--phone` **必填**，会写进授权码，作为远程停用的匹配键。
- `--machine` 必填，必须是新版 `TK2-` 设备码；除非显式使用 `--any`（内部测试 / 不绑定设备）。
- `--note` 只是展示备注，通常是购买渠道或订单号。

输出示例：

```
[license] 手机号： 13800000000
[license] 设备码： TK2-D0C4-0D13-4FD5-0000-0E3F-A04D
[license] 有效期： 2026-12-20
[license] 激活码：
TUKU1.eyJ2IjoxLCJwcm9kdWN0IjoidHVrdSIs...
```

把最后一行（`TUKU1.` 开头）完整发给用户即可。

### 3.4 参数说明

| 参数 | 说明 | 默认 |
| --- | --- | --- |
| `--phone <手机号>` | 必填；5–20 位数字，可带 `+` | 无 |
| `--machine <设备码>` | 新版 `TK2-...` 设备码；必填，除非用 `--any` | 无 |
| `--days <N>` | 有效天数；`0` = 永久 | `365` |
| `--expires <YYYY-MM-DD>` | 指定到期日（优先于 `--days`） | 无 |
| `--note <文本>` | 备注，通常是订单号 / 渠道；会显示在用户设置页 | 空 |
| `--edition <名称>` | 版本名，目前只有 `pro` | `pro` |
| `--any` | 不绑定设备（试用 / 内部测试） | 关 |
| `--out <路径>` | 同时把激活码写进文件，例如 `licenses/buyer-2026.key` | 不写 |

有效期规则：只写日期时按**当天 23:59:59** 失效；`--days 30` 按「含今天」计算，设置页显示剩余 30 天。

### 3.5 用户激活

用户在「设置 → 授权」粘贴激活码 → 点「激活」，立即生效，无需重启。

## 4 常见场景

| 场景 | 做法 |
| --- | --- |
| 年费续期 | 用同一手机号 + 同一设备码再签一张更晚到期的授权，让用户重新粘贴覆盖 |
| 换电脑 | 新设备码重新签一张；旧授权文件留在旧机器上，无需处理 |
| 用户重装系统 / 换硬盘 | 设备码 6 组里通常只变 1 组，原授权仍可用；变 3 组及以上再重签 |
| 一个手机号多台设备 | 在管理工具里一次填多个设备码，或用命令行逐台签发 |
| 一台设备多个手机号 | 同一设备码分别签给不同手机号；用户本机同一时间只能激活其中一份 |
| 试用 | `--phone ... --any --days 14`，到期后专业版能力自动关闭 |
| 团队 / 内部 | `--phone ... --any --days 0`，不绑定设备；**不要外发**，等同于万能钥匙 |
| 批量发货 | 用管理工具一次填多行设备码，或统一加 `--out licenses/<订单号>.key` 留档 |
| 退款 / 违约 | 在管理工具里停用该手机号或设备；客户端拉到停用清单后锁定 |

## 5 用户侧会看到什么

- **免费版**：全部基础功能可用（浏览、整理、搜索、堆叠、笔记、基础查看等）。
- **专业版**：额外开放：
  1. 条码分文件夹与产品图上传（`/api/barcode`）
  2. 时间线（`/api/timeline`）
  3. 无限画布（前端页面）
  4. 调色 / 裁切 / 修图（`/api/edit`、`/api/images/:id/crop|adjust|...`）
  5. 批量编辑 / 导出 / 增强 / 整理 / 动作（`/api/enhance`、`/api/export`、`/api/tidy`、批量路由）
  6. 局域网投送与只读分享（`/api/lan`）
  7. 插件脚本执行（`/api/plugins/:id/run`）
  8. AI 夜间批处理（`/api/night-batch`）
- 免费版点这些功能会收到明确提示：「需要专业版授权，请在『设置 → 授权』中激活」，不会静默失败。
- 授权卡片显示：版本、手机号、设备码、到期日、剩余天数、签发备注，以及设备码的计算方式与变更条件。
- 「取消授权」只删除本机授权文件，不影响用户手里的激活码，重新粘贴即可恢复。
- 开发环境如果设置了 `TUKU_DEV_PRO=1`，卡片会显示「开发模式 Pro」；此时取消授权只会删授权文件，**不会关闭环境变量带来的 Pro**，页面会明确提示。安装包不要带这个变量。

## 6 故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 提示「激活码格式不正确」 | 复制不全、被邮件折行 | 让用户重新完整复制 `TUKU1.` 开头的整段 |
| 提示「签名无效」 | 激活码被改过 / 复制缺字符 | 重新发送原始激活码 |
| 提示「与当前机器不符」 | 换了机器，或 2 项以上硬件变化 | 让用户发新设备码，重新签发 |
| 提示「授权已过期」 | 到期 | 续期重签 |
| 提示「该手机号或设备已被远程停用」 | 管理工具里停用了手机号 / 设备 | 在管理工具解除停用，等客户端下次刷新授权 |
| 激活成功但功能仍被挡 | 服务端进程未更新（老版本） | 升级到含授权模块的版本后重试 |
| 设置页显示「未内置授权公钥」 | 打包时漏了 `server/license-public.pem` | 检查打包产物，确认 `server/**/*` 被包含 |
| 修改硬件后设备码变了 | 正常 | 6 组允许变 2 组，且强特征要命中；主要硬件变化需重签 |
| 管理工具打不开 / 401 | 浏览器版没用带 `?token=` 的地址，或工具已重启；双击版直接重新打开 | 用启动日志里的最新地址，或双击 exe |
| 双击版提示「需要授权私钥」 | 私钥不在 exe 同目录 / 用户数据目录 | 点「选择私钥文件」导入 `.license-private.pem`，之后会记住 |

设备码（v2）由这些项各取 4 位组成：

1. SMBIOS UUID
2. 主板序列号 + BIOS 序列号
3. 启动盘物理序列号
4. TPM 背书密钥（可用时）
5. Windows `MachineGuid`
6. CPU `ProcessorId` / 型号 + 物理网卡 MAC

读不到的项显示为 `0000`，不参与比对；可比较项少于 3 项时判定无法识别。旧版 16 位设备码仍可用于验证已售旧授权，但不能再新签。

## 8 安全红线

1. **私钥不进仓库、不进聊天记录、不放 CI 明文**；CI 需要签发时用 secret 注入 `TUKU_LICENSE_PRIVATE_KEY`。
2. **已发布的公钥永远不要换**。老安装包只认旧钥匙，换公钥等于让老用户无法激活。
3. 热更包可以改 `server/` 下的 JS，但**不要**通过热更替换授权逻辑或公钥，否则会出现「同一个版本、两台机器行为不同」的排查噩梦。
4. 通用授权（`--any`）只用于试用与内部，发放记录单独留档。
5. 建议主推**年费**：离线授权没有在线租约；需要收回时用停用清单（客户端需能联网拉到清单）。

## 9 技术附录

### 9.1 授权码结构

```
TUKU1.<base64url(payloadJson)>.<base64url(ed25519 签名)>
```

payload 字段：

```json
{
  "v": 1,
  "product": "tuku",
  "edition": "pro",
  "machine": "TK2-D0C4-0D13-4FD5-0000-0E3F-A04D",
  "machine2": "TK2-D0C4-0D13-4FD5-0000-0E3F-A04D",
  "phone": "13800000000",
  "account": "13800000000",
  "issuedAt": "2026-11-20",
  "expires": "2026-12-20",
  "note": "buyer@example.com",
  "seats": 1
}
```

- `machine2` 是 v2 设备码，新客户端优先按它校验（6 组、允许 2 组漂移、强特征至少命中 1 组）。
- `machine` 在新码里与 `machine2` 相同：老客户端会按 v1 比对而安全拒绝，避免把新码当成「不绑定设备」。
- 老授权码只有 `machine`（16 位 v1）：新客户端自动回退到 v1 规则，已售授权继续有效。
- `machine` 为空 = 不绑定设备（内部授权）。
- `phone` 是账号标识；`account` 为兼容旧客户端与手机号保持一致。
- 签名覆盖 payload 的原始字节，任何字段改动都会验签失败。
- 也接受 `{"key":"TUKU1..."}` 形式的 JSON（用户存文件后粘贴时常见）。

### 9.2 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/license` | 当前状态；`?refresh=1` 重新探测硬件 |
| `POST` | `/api/license/activate` | body `{ "key": "TUKU1..." }` |
| `POST` | `/api/license/deactivate` | 删除本机授权文件 |

未授权时受控接口返回：

```json
{ "error": "「局域网投送与只读分享」需要专业版授权，请在「设置 → 授权」中激活", "code": "license_required", "feature": "lan" }
```

### 9.3 环境变量

| 变量 | 作用 |
| --- | --- |
| `TUKU_LICENSE_PUBLIC_KEY` | 覆盖内置公钥（CI / 测试用） |
| `TUKU_LICENSE_PRIVATE_KEY` | 签发脚本 / 管理工具读取私钥（CI secret） |
| `TUKU_LICENSE_REVOKE_URL` | 覆盖默认停用清单地址（默认见下） |
| `TUKU_LICENSE_REVOKE_DISABLE` | **仅开发 / CI**：设为 `1` 关闭停用检查；安装包禁止携带 |
| `TUKU_LICENSE_ADMIN_PORT` | 管理工具端口，默认 `3199` |
| `TUKU_LICENSE_ADMIN_DATA` | 管理工具数据目录，默认仓库下 `licenses/` |
| `TUKU_NO_OPEN` | 设为 `1` 时管理工具不自动打开浏览器 |
| `TUKU_DEV_PRO` | 仅开发环境：`1` = 不写授权文件也临时打开 Pro；安装包禁止携带 |
| `TUKU_BUY_URL` | 设置页显示「购买专业版」按钮的地址 |

| `web/src/pages/settings/LicenseCard.tsx` | 设置页授权卡片（含设备码说明） |
| `test/license.test.mjs` | 授权单测 |

### 9.5 扩展一项专业版能力

1. 在 `server/lib/license-core.js` 的 `PRO_FEATURES` 加一项 `{ key, label }`。
2. 在 `server/app.js` 里给对应路由挂 `app.use('/api/xxx', requirePro('xxx'))`，或在单个路由上挂 `requirePro('xxx')`。
3. 设置页的授权卡片会自动列出这项能力（前端按 key 配文案的话，在 `LicenseCard.tsx` 的 `FEATURE_LABELS` 补一条）。
4. 在 `test/license.test.mjs` 与 `scripts/smoke.mjs` 补一条「免费 402 / 激活后 200」的断言。

## 10 远程停用（离职 / 违约管理）

默认清单地址（客户端内置）：

```text
https://gitee.com/mr-awei/youyouvault/raw/main/docs/license/license-revoke.json
```

仓库里已经提交了一份**签名过的空清单** `docs/license/license-revoke.json`。这份文件就是线上停用清单，不要删除。

推荐直接在图形工具里操作：授权记录里点「取消设备授权」，或对手机号点「停用手机号」；工具会递增 `seq`、重新生成清单。然后：

1. 在「停用清单」页点「写入发布文件」，覆盖仓库里的 `docs/license/license-revoke.json`
2. `git add docs/license/license-revoke.json && git commit && git push`
3. 客户端在启动时和每 30 分钟自动拉取；断网 / 拉不到 / 验签失败会**临时禁用**，直到下一次成功连上且清单里没有命中它。

命令行等价操作：

```bash
node scripts/license-issue.mjs --phone 13800000000 --machine TK2-D0C4-0D13-4FD5-0000-0E3F-A04D --days 365
node scripts/license-revoke.mjs --phone 13800000000 --seq 2 --out docs/license/license-revoke.json
git add docs/license/license-revoke.json && git commit -m "chore(授权): 更新停用清单" && git push
```

- 手机号停用：该手机号下所有设备一起锁定。
- 只停用单台设备：`--machine TK2-...`（也接受旧版 16 位设备码）
- `--seq` 必须递增；客户端拒绝比本地缓存更旧的清单
- 生成空清单：`node scripts/license-revoke.mjs --empty --seq 1 --out docs/license/license-revoke.json`

### 失败关闭规则

- **已安装真实授权**的客户端：启动时先阻塞检查一次，之后每 30 分钟检查。
  - 拉不到文件、HTTP 错误、签名不对 → `checkFailed=true`，数据接口全部 403，界面显示「授权检查失败，软件已临时禁用」。
  - 下一次检查成功且清单未命中该手机号 / 设备 → 自动恢复正常；界面上的「立即重试」可手动触发。
  - 本地缓存只在“检查成功”时用于判断是否命中；**不能**用旧缓存绕过断网禁用。
- **未安装授权**（免费版）不因断网被锁，但专业版能力本来就不可用。
- 开发 / CI 用 `TUKU_LICENSE_REVOKE_DISABLE=1` 关闭检查；安装包不会带这个变量。
- 停用清单和授权码共用同一把 Ed25519 公钥；私钥仍然只在发行方手里。
- 完全离线且从未联网的机器会因失败关闭而不可用；这是“必须能连上清单”的代价。

## 11 安全打包与还原（调试用）

打包发布建议用：

```bash
npm run dist:secure
```

它会在打包前用 esbuild 对 `electron/` 与 `server/` 的所有 JS 做压缩/标识符混淆，打包完成后**自动还原**源码。

- 源码备份：`.obfuscate-backup/<时间戳>/`（不进安装包，已在 `.gitignore`）
- 打包被中断、源码停在混淆状态时：

  ```bash
  npm run obfuscate:restore
  ```

- 本地调 Bug 时跳过混淆：

  ```bash
  TUKU_SKIP_OBFUSCATE=1 npm run dist
  ```

> 客户端代码无法做到「绝对不可逆」。混淆能提高逆向成本，但不能替代服务端校验；授权、远程停用、Pro 能力闸都在服务端/本地授权层，不要只靠前端隐藏按钮。

### 11.1 授权管理工具打包（双击版）

```bash
npm run license:admin:dist
```

产物：`release-build/license-admin/TuKu-LicenseAdmin-<版本>.exe`，双击直接打开窗口。

- 主进程、管理服务、授权核心用 esbuild 打成一个 ESM 文件，**不依赖仓库 node_modules**；
- 在仓库外临时目录打包，避免把主项目的 sharp / onnxruntime / react 误装进去；
- 首次运行找不到私钥会弹窗选择 `.license-private.pem`，导入后保存到用户数据目录；
- 工具只需要 exe + 公钥（已打进包），私钥始终由作者本机保管。

## 12 一键诊断包

设置 → 关于软件 → **生成诊断包（ZIP）**。

zip 内包含：

- `meta.json`：系统版本、CPU/内存、Electron/Node、时区、路径
- `network.json`：网卡、代理环境变量、主机名
- `settings.json`：设置项（password/token/apiKey/secret 等已替换为 `***`）
- `license.json`：授权状态、手机号、设备码、是否被停用（不含授权码原文）
- `oms.json`：OMS 配置状态（不含密码）
- `actions.json`：最近 200 条操作日志
- `client.json`：浏览器/渲染进程环境与当前页面
- `logs/`：最近的 `.log/.err`（token、Bearer、授权码已脱敏）
- `description.txt`：用户填写的问题描述/复现步骤

用户提交 Bug 时只需要发这个 zip。
