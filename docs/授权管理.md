# 图库授权管理操作手册

面向软件的**发行方**与**售后支持**。说明 1.5.0 起如何签发、批量签发、取消、恢复、停用、发布清单与排查故障。

核心口径只有一条：

> **一个授权码 = 一个手机号 + 一台设备码。** 同一台设备多人使用时，每个手机号各有一张授权码；取消其中一条，不影响同一台设备上的其他手机号。

## 1 1.5.0 的授权模型

| 规则 | 说明 |
| --- | --- |
| 一对一是唯一口径 | 每张授权码同时签入手机号和设备码，换机器验不过 |
| 同一设备多人使用 | 每个手机号各签一张，互不影响；取消某一条只停用「手机号 + 设备码」这一对 |
| 一个手机号多台设备 | 逐台签发，每台一张。批量授权必须**逐行成对**，不能一个手机号扇出多台设备 |
| 停用手机号 | 该手机号生成的所有授权码一起失效 |
| 停用设备 | 兼容旧的按设备整体停用；1.5.0 的日常操作以「取消某条授权」和「停用手机号」为主 |
| 恢复 | 恢复某条授权 = 从停用清单移除该「手机号 + 设备码」；若该手机号之前被整体停用，恢复其中任意一条会解除手机号级停用，该手机号名下所有授权一起恢复 |

1.5.0 的主要变化：

- 授权管理工具改为「授权 / 已授权 / 已停用」三个页签，取消与恢复都支持多选批量操作。
- 停用清单新增 `revokedPairs`，可以按「手机号|设备码」精确停用，不再只能按手机号或设备整体停用。
- 客户端同时识别 `revokedPhones`、`revokedMachines`、`revokedPairs`。
- **只有明确命中停用记录才整体锁定数据接口**；联网失败只退回免费版，网络恢复后自动恢复专业版。
- 打包版忽略用于打开 Pro / 替换公钥 / 关闭停用校验的环境变量，并增加验签器负向自检。
- 每台设备首次安装提供 7 天完整专业版试用；未打包的开发环境默认拥有专业版能力。

## 2 授权系统由什么组成

| 角色 | 放在哪里 | 说明 |
| --- | --- | --- |
| 私钥 | 你的本机 `.license-private.pem` | 只用来签发授权码与停用清单；泄露 = 谁都能签 |
| 公钥 | `server/license-public.pem` | 随安装包发布，客户端用它验签；可以提交到仓库 |
| 授权码 | 发给用户的一串文本 | `TUKU1.<payload>.<signature>`，离线可验 |
| 手机号 | 用户购买时提供 | 写进授权码，作为账号标识与停用匹配键 |
| 设备码 | 用户软件「设置 → 授权」里显示 | 形如 `TK2-XXXX-XXXX-XXXX-XXXX-XXXX-XXXX` |
| 授权文件 | 用户数据目录 `data/license.key` | 激活成功后写入，跨资源库共用 |
| 停用清单 | `docs/license/license-revoke.json` | 签名后的 `TUKU-REVOKE1...` 文本，客户端定时拉取 |
| 管理台账 | `licenses/admin.json` | 管理工具本机记录，含完整激活码，**不要提交** |

三条原则：

1. **不联网也能激活**：授权码验签是本地计算，断网可用，不需要你维护激活服务器。
2. **绑定手机号 + 设备码**：授权码里同时签了二者，换机器验不过；停用按二者精确匹配。
3. **停用需要联网**：客户端要能拉到签名停用清单，才能知道某条授权已被取消。

## 3 首次准备

### 3.1 生成密钥对

```bash
node scripts/license-keygen.mjs
```

- 公钥 → `server/license-public.pem`（**提交进仓库**，随安装包发布）
- 私钥 → `.license-private.pem`（已在 `.gitignore`，**绝不提交**）

当前仓库已经生成过一对密钥。脚本检测到公钥存在会拒绝覆盖。

### 3.2 备份私钥

把 `.license-private.pem` 的**全文**存进密码管理器，再存一份到离线介质。

- 丢了：老用户不受影响，但你无法再为新机器签发。
- 泄露：立刻停止发货；已发布安装包里的公钥换不掉，只能靠新版本 + 新密钥重建授权体系。

### 3.3 确认私钥没有进仓库

```bash
git status --short
git ls-files | findstr license-private
```

第二条应当没有任何输出。

## 4 启动授权管理工具

### 4.1 三种启动方式

```bash
npm run license:admin          # 浏览器版（本地网页）
npm run license:admin:app      # Electron 窗口版
npm run license:admin:dist     # 打包可双击的 exe
```

打包产物：

```text
release-build/license-admin/TuKu-LicenseAdmin-<版本>.exe
```

双击即可打开独立窗口。首次运行如果找不到私钥，会弹窗让你选择 `.license-private.pem`，导入后保存在本机用户数据目录，之后双击即用。

### 4.2 浏览器版的访问地址

管理服务只监听 `127.0.0.1`，启动时随机生成访问令牌，并打印带令牌的地址：

```text
http://127.0.0.1:3199/?token=...
```

- 默认端口 `3199`，可用 `TUKU_LICENSE_ADMIN_PORT` 修改。
- 用启动日志里带 `?token=` 的地址打开；令牌不对会显示「需要访问令牌」。
- 不想自动打开浏览器时：`TUKU_NO_OPEN=1 npm run license:admin`。

### 4.3 数据放在哪里

| 形态 | 台账与本地清单 |
| --- | --- |
| 开发态（命令行 / Electron 未打包） | 仓库下 `licenses/admin.json`、`licenses/license-revoke.json` |
| 双击版（已打包） | 用户数据目录下的 `licenses/`，页面顶部会显示完整路径 |
| 自定义 | `TUKU_LICENSE_ADMIN_DATA=<目录> npm run license:admin` |

台账含完整激活码，已在 `.gitignore`，**不要提交**。

### 4.4 私钥从哪里读取

管理工具会在这些位置查找私钥：

- 环境变量 `TUKU_LICENSE_PRIVATE_KEY`
- Electron 窗口版的用户数据目录（首次运行选择后保存的位置）
- 仓库根 `.license-private.pem`
- `tools/license-admin/.license-private.pem`
- exe 同目录及其上几级目录
- 当前工作目录

找不到私钥时工具仍能打开，但只能查看，不能签发或更新停用清单。页面右上角会显示「未找到私钥」。

## 5 单个授权

打开「授权」页 → 「单个授权」卡片。

| 字段 | 填写规则 |
| --- | --- |
| 手机号 | 5–20 位数字，可带 `+`；空格、横线会被规范化掉 |
| 设备码 | `TK2-` 开头的 24 位十六进制；带不带横线都行 |
| 有效期 | 30 天 / 90 天 / 180 天 / 1 年 / 2 年 / 永久 / 自定义到期日 |
| 备注 | 可选，通常是订单号、购买渠道或对接人 |

点「生成授权码」后：

- 工具用私钥签发；找到公钥时会立即回验一次，公私钥不配对或自检失败会直接报错，不会把坏码发出去。
- 同一手机号 + 同一设备码再次签发会**覆盖旧记录并更新有效期**，适合续期。
- 签发结果显示手机号、设备码、到期日与完整授权码，可单条复制。
- 「复制全部」按「手机号 / 设备码 / 到期日 / 授权码」导出；「下载 TXT」保存整批结果。

有效期规则：只写日期时按当天 `23:59:59` 失效；选 `30 天` 按「含今天」计算，设置页显示剩余 30 天。

## 6 批量授权

打开「授权」页 → 「批量授权」卡片。

### 6.1 格式

**一行只能是一对「手机号 + 设备码」**，手机号在前、设备码在后，空格 / 逗号 / Tab 分隔：

```text
13800000000 TK2-A1B2-C3D4-E5F6-7890-ABCD-EF01
13900001111,TK2-B2C3-D4E5-F6A7-8901-BCDE-F012
13700002222	TK2-C3D4-E5F6-A7B8-9012-CDEF-0123
```

### 6.2 硬性限制

- **不能一个手机号扇出多台设备**。同一人多台设备请写多行，每行都写手机号。
- 一次最多 500 条。
- 完全相同的「手机号 + 设备码」在本次请求里只签一次。
- 旧版 16 位设备码会被拒绝，并提示「已不能用于新签发」；让用户升级客户端后复制 `TK2-` 新码。
- 整批共用同一个有效期与同一个备注。
- 任意一行格式不正确，整批都不会签发，并指出是第几行。

生成后同样显示在「签发结果」区，可复制全部或下载 TXT。

## 7 已授权列表

「已授权」页展示**所有未停用的记录**，包括已过期记录（状态会标为「已过期」）。顶部统计显示有效、已停用、7 天内到期、手机号数量与授权记录总数。

| 列 | 说明 |
| --- | --- |
| 手机号 / 备注 | 手机号为主，备注在下方 |
| 设备码 | `TK2-...`；旧版 16 位会标注「旧版 16 位」 |
| 状态 | 有效 / 已过期（已停用的记录在「已停用」页） |
| 签发 | 签发日期 |
| 到期 | 到期日与剩余天数；永久显示「永久」 |
| 操作 | 复制授权码 / 取消授权 |

### 7.1 搜索与复制

- 搜索框匹配手机号、设备码、备注。
- 行内「复制」只复制该条授权码；「全选」与行首复选框用于多选。

### 7.2 取消授权

- 单条点「取消授权」，或多选后点「取消选中授权（N）」。
- 确认框会明确提示：**只会停用对应的「手机号 + 设备码」，同一台设备上的其他手机号不受影响**。
- 取消会写入 `revokedPairs`，递增 `seq`，并重新生成管理工具本地的停用清单。
- 客户端需要拉到新清单后才会生效；见第 11 节「停用清单与发布」。

### 7.3 导入旧激活码

「导入旧激活码」会扫描管理数据目录及附近 `licenses/` 下的 `.key` / `.txt`，把带手机号与设备码的旧激活码补进台账。没有手机号、产品或设备码不合法的旧授权会被跳过。

## 8 已停用列表

「已停用」页展示状态为「已停用」的记录，并标注停用原因：

| 停用原因 | 含义 |
| --- | --- |
| 已取消授权 | 只停用了这一条「手机号 + 设备码」 |
| 手机号停用 | 该手机号名下所有授权一起失效 |
| 设备停用 | 该设备名下所有授权一起失效（兼容旧记录） |

### 8.1 复制与恢复

- 行内「复制」仍可复制原授权码。
- 单条「恢复授权」，或多选后「恢复选中授权（N）」。
- 恢复会：
  - 从 `revokedPairs` 移除这一对；
  - 从 `revokedPhones` 移除该手机号；
  - 从 `revokedMachines` 移除该设备。
- 因此，**如果该手机号之前被整体停用，恢复其中任意一条会解除手机号级停用，该手机号名下所有授权一起恢复**。确认框会给出这一提示。

### 8.2 旧的按手机号 / 设备停用

页面底部会显示历史遗留的「按手机号 / 设备停用」记录（如果有），每项带「恢复」按钮。恢复手机号会影响该手机号下所有授权；恢复设备会影响该设备下所有授权。

## 9 停用手机号

在「已授权」页顶部：

```text
[输入手机号，停用其全部授权码] [停用手机号]
```

- 该手机号生成的所有授权码都会失效，不区分设备。
- 停用后，相关记录会出现在「已停用」页，原因为「手机号停用」。
- 需要恢复时，在「已停用」页恢复该手机号名下任意一条（或使用页面底部的手机号恢复项）。注意：这会让该手机号名下所有授权一起恢复。
- 只想停用某个人的一台设备时，不要用「停用手机号」，请在「已授权」列表里取消对应那一条。

## 11 停用清单与发布

打开「已停用」页 → 展开「停用清单与发布」。

### 11.1 页面会显示什么

| 项 | 说明 |
| --- | --- |
| 清单文件 | 管理工具本机生成的 `license-revoke.json` |
| 本机地址 | `http://127.0.0.1:<端口>/license-revoke.json`，仅供本机调试 |
| 发布文件 | 仓库里的 `docs/license/license-revoke.json`；找不到时显示「未找到仓库发布文件」 |
| Gitee 地址 | 客户端默认拉取的线上地址 |
| 清单内容 | 完整的 `TUKU-REVOKE1...` 签名文本 |
| seq | 当前清单序号，必须递增 |

可复制清单内容、复制本机地址、复制 Gitee 地址或下载 JSON。

### 11.2 发布步骤

1. 在工具里完成取消 / 停用操作；工具会自动递增 `seq` 并生成本地清单。
2. 点「写入发布文件」，覆盖仓库里的：

   ```text
   docs/license/license-revoke.json
   ```

3. 提交并推送：

   ```bash
   git add docs/license/license-revoke.json
   git commit -m "chore(授权): 更新停用清单"
   git push
   ```

客户端默认从以下地址拉取：

```text
https://gitee.com/mr-awei/youyouvault/raw/main/docs/license/license-revoke.json
```

- 客户端在**启动时**、之后**每 30 分钟**、以及激活 / 取消授权后刷新时拉取；拉取失败后最多每分钟重试一次。
- 拉取后用内置公钥验签；验签通过才写入本地缓存。
- 启动时若本机已安装授权，会阻塞等待这一次检查；免费版不阻塞启动。

### 11.3 seq 规则

- `seq` 必须严格递增；客户端不会用更旧的清单覆盖本地缓存。
- 管理工具启动时会读取发布文件里的 `seq`，保证后续生成的新清单大于线上版本。
- 点「写入发布文件」时，如果发现发布文件的 `seq` 已经不小于本地值，会先把本地 `seq` 提到「发布值 + 1」。

### 11.4 命令行等价操作

```bash
# 签发
node scripts/license-issue.mjs --phone 13800000000 --machine TK2-D0C4-0D13-4FD5-0000-0E3F-A04D --days 365

# 按手机号停用
node scripts/license-revoke.mjs --phone 13800000000 --seq 2 --out docs/license/license-revoke.json

# 按设备停用
node scripts/license-revoke.mjs --machine TK2-D0C4-0D13-4FD5-0000-0E3F-A04D --seq 3 --out docs/license/license-revoke.json

# 生成空清单
node scripts/license-revoke.mjs --empty --seq 1 --out docs/license/license-revoke.json
```

> 命令行 `license-revoke.mjs` **不支持 `revokedPairs`**，并且会覆盖整个发布文件。需要「只停用某一条手机号 + 设备码」时，请用图形工具取消授权，不要用命令行重写清单。

## 12 用户侧激活与状态

### 12.1 用户提供什么

用户打开「设置 → 授权」，复制两样东西发给管理员：

- **手机号**：用户自己的手机号。
- **设备码**：`TK2-` 开头的 24 位码，可点「复制」。

只发其中一个无法签发。

### 12.2 激活流程

用户在「设置 → 授权」粘贴完整激活码 → 点「激活」。

- 客户端先检查外形是否为 `TUKU1.xxx.yyy`。
- 服务端用内置公钥做 Ed25519 验签，并校验产品、设备码、有效期。
- 只有本机验签通过且写入授权文件后，`licensedByKey` 才为 `true`，界面才提示激活成功。
- 开发环境的 Pro 或 7 天试用不会被当成「这个激活码有效」。

### 12.3 授权卡片会显示什么

- 版本、手机号、设备码、到期日、剩余天数、签发备注。
- 设备码的计算方式、会变化的情况与容错规则。
- 停用清单最近一次检查时间与错误原因（如果有）。
- 7 天试用的剩余天数或到期提示。
- 开发环境下会额外标注「开发模式 Pro」，并说明取消授权不会关闭开发环境自带的专业版。

「取消授权」只删除本机 `data/license.key`，不影响用户手里的激活码，重新粘贴即可恢复。

### 12.4 被停用与联网失败的区别

| 状态 | 表现 |
| --- | --- |
| 明确被停用 | `revoked = true`，数据接口整体返回 403，界面提示「该手机号或设备已被远程停用」 |
| 拉取清单失败 | `checkFailed = true`，只退回免费版，界面提示「无法连接授权服务器」；网络恢复后自动恢复专业版 |
| 授权过期 | 退回免费版，提示续期 |
| 免费版 | 不因断网被锁，但专业版能力本来就不能用 |

## 13 常见故障

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 激活码格式不正确 | 复制不全、被邮件折行、不是 `TUKU1.` 开头 | 让用户重新完整复制 |
| 激活码签名长度不正确 | 激活码被截断或篡改 | 重新发送原始激活码 |
| 激活码签名无效 | 内容被改过、复制缺字符 | 重新发送原始激活码 |
| 激活码不属于这个产品 | 拿错了产品的授权码 | 核对产品标识，重新签发 |
| 激活码版本不受支持 | 客户端与授权码版本不匹配 | 升级客户端或改用对应版本的签发工具 |
| 与当前设备不符 | 换了机器，或硬件变化超出容错范围 | 让用户发新设备码，重新签发 |
| 无法读取当前设备码 | 硬件探测失败或平台不支持 | 让用户重启后重试；仍失败则收集诊断信息 |
| 授权已于某日过期 | 到期 | 用同一手机号 + 同一设备码续期 |
| 该手机号或设备已被远程停用 | 停用清单命中 | 在管理工具恢复对应授权，发布清单，让客户端刷新 |
| 无法连接授权服务器 | 断网、代理、Gitee 不可达、验签失败 | 只退回免费版，不是停用；网络恢复后自动恢复。可让用户手动刷新授权 |
| 授权校验模块异常，已退回免费版 | 验签器负向自检失败，代码可能被改过 | 让用户重新安装官方客户端 |
| 激活成功但专业版功能仍被挡 | 授权未真正写入、服务端版本过旧、或授权已被停用 | 查看 `licensedByKey` 与 `revoked`，确认服务端版本 |
| 设置页显示「未内置授权公钥」 | 打包时漏了 `server/license-public.pem` | 检查打包产物，确认 `server/**/*` 被包含 |
| 管理工具 401 | 没有用带 `?token=` 的地址，或工具已重启 | 用启动日志里的最新地址；双击版重新打开 |
| 双击版提示「需要授权私钥」 | 私钥不在 exe 同目录 / 用户数据目录 | 点「选择私钥文件」导入 `.license-private.pem` |
| 提示旧版设备码不能新签 | 用户仍在用 16 位旧设备码 | 让用户升级客户端后复制 `TK2-` 新码 |
| 批量授权第 N 行格式不正确 | 该行不是「手机号 + 设备码」成对格式，或少了其中一项 | 改成一行一对；多台设备写多行，不要一个手机号扇出 |
| 写入发布文件 404 | 没从仓库目录启动工具，或 `docs/license/license-revoke.json` 不存在 | 从仓库目录启动，或手动复制清单内容到该文件 |
| 写入发布文件后客户端没变化 | 还没 `git push`、客户端未到 30 分钟刷新、或清单 `seq` 没递增 | 推送后手动刷新授权，确认 `seq` 与线上文件 |
| 修改硬件后设备码变了 | 正常 | 6 组允许在可读组足够时变 2 组，且至少命中 1 个强特征；主要硬件变化需重签 |

## 14 安全边界

1. **私钥不进仓库、不进聊天记录、不放 CI 明文**；CI 需要签发时用 secret 注入 `TUKU_LICENSE_PRIVATE_KEY`。
2. **已发布的公钥永远不要换**。老安装包只认旧钥匙，换公钥等于让老用户无法激活。
3. **客户端离线授权无法做到绝对不可破解**。`dist:secure` 会对 `license.js` / `license-core.js` 额外做字符串加密、Base64、控制流扁平化与 self-defending 混淆，但那只提高逆向成本；真正的边界是私钥不入包、验签在本地、停用清单需签名。
4. **打包版不认测试开关**：`TUKU_DEV_PRO` 已不参与判断；`TUKU_LICENSE_PUBLIC_KEY`、`TUKU_LICENSE_REVOKE_DISABLE`、`TUKU_STRICT_LICENSE`、`TUKU_TRIAL_DISABLE` 只在未打包的开发 / CI 环境生效。安装包不能靠环境变量打开 Pro、替换公钥或关闭停用校验。
5. **验签器有负向自检**：如果授权校验被改成「永远返回 true」，自检失败，客户端按免费版运行。
6. **停用依赖联网**：明确停用后，客户端要拉到签名清单才会锁定；完全离线且从未联网的机器无法感知新停用。联网失败只会退回免费版，不会误锁软件。
7. **管理工具只监听本机**，令牌每次启动随机生成；台账含完整激活码，`licenses/` 不要提交。
8. **不要通过热更替换授权逻辑或公钥**，否则会出现「同一个版本、两台机器行为不同」的排查噩梦。

## 16 技术附录

### 16.1 授权码结构

```text
TUKU1.<base64url(payloadJson)>.<base64url(ed25519 签名)>
```

payload 字段：

```json
{
  "v": 1,
  "product": "tuku",
  "edition": "pro",
  "machine": "TK2-D0C4-0D13-4FD5-0000-0E3F-A04D",
  "machine2": "TK2-D0C4-0D13-4FD5-0000-0E3F-A04D",
  "phone": "13800000000",
  "account": "13800000000",
  "issuedAt": "2026-11-20",
  "expires": "2027-11-20",
  "note": "订单号 / 渠道",
  "seats": 1
}
```

- `machine2` 是 24 位 v2 设备码，新客户端优先按它校验。
- 新签发时 `machine` 与 `machine2` 相同：老客户端会按 v1 规则比对而安全拒绝，避免把新码当成「不绑定设备」。
- 老授权码只有 16 位 `machine`：新客户端自动回退到 v1 规则，已售授权继续有效。
- `machine` 为空 = 不绑定设备（仅内部测试，对应签发脚本的 `--any`）。
- 签名覆盖 payload 的原始字节，任何字段改动都会验签失败。
- 也接受 `{"key":"TUKU1..."}` 形式的 JSON。
- 验签时的硬校验：激活码总长 ≤ 8192、payload JSON ≤ 4096、Ed25519 签名固定 64 字节、`product === "tuku"`、`v === 1`、未过期、设备码匹配。

### 16.2 停用清单结构

```text
TUKU-REVOKE1.<base64url(payloadJson)>.<base64url(ed25519 签名)>
```

payload 示例：

```json
{
  "v": 1,
  "product": "tuku",
  "seq": 3,
  "issuedAt": "2026-11-22T08:00:00.000Z",
  "revokedPhones": ["13800000000"],
  "revokedAccounts": ["13800000000"],
  "revokedMachines": ["D0C40D134FD500000E3FA04D"],
  "revokedPairs": ["13800000000|D0C40D134FD500000E3FA04D"]
}
```

- `revokedPhones`：按手机号整体停用。
- `revokedAccounts`：兼容旧客户端的同义字段，管理工具写入时与 `revokedPhones` 保持一致。
- `revokedMachines`：按设备整体停用，值可以是 24 位 v2 或 16 位 v1。
- `revokedPairs`：按「手机号|设备码」精确停用；也接受 `{ "phone": "...", "machine": "..." }` 对象写法。
- 客户端会分别检查：手机号是否在 `revokedPhones` / `revokedAccounts`、当前「手机号 + 设备码」是否在 `revokedPairs`、当前设备是否在 `revokedMachines`。任一命中即停用；只有 `revokedPairs` 命中时，影响范围限于这一对。

### 16.3 客户端授权接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/license` | 当前状态；`?refresh=1` 重新探测硬件并强制刷新停用清单 |
| `POST` | `/api/license/activate` | body `{ "key": "TUKU1..." }` |
| `POST` | `/api/license/deactivate` | 删除本机授权文件 |

未授权时受控接口返回：

```json
{
  "error": "「局域网投送与只读分享」需要专业版授权，请在「设置 → 授权」中激活",
  "code": "license_required",
  "feature": "lan"
}
```

明确被停用时，除授权状态、诊断包与系统信息外的 `/api` 接口返回 `403`：

```json
{ "error": "该手机号或设备已被远程停用，请联系管理员", "code": "account_revoked" }
```

### 16.4 管理工具本地接口

仅监听 `127.0.0.1`，需要 `Authorization: Bearer <token>`（也接受 `x-admin-token` 或 `?token=`）：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/state` | 台账、统计、停用列表、清单内容 |
| `POST` | `/api/issue` | 单个授权；body `{ phone, machine, days/expires, note, edition }` |
| `POST` | `/api/issue-batch` | 批量授权；body `{ pairs: [{ phone, machine }, ...] }` |
| `POST` | `/api/cancel` | 按记录 id 取消授权，写入 `revokedPairs` |
| `POST` | `/api/restore` | 按记录 id 恢复授权，同时移除手机号 / 设备级停用 |
| `POST` | `/api/revoke` | 兼容的按手机号 / 设备整体停用；body `{ scope: "phone" \| "machine", value, revoked }` |
| `POST` | `/api/publish` | 把当前清单写入 `docs/license/license-revoke.json` |
| `POST` | `/api/import-legacy` | 扫描并导入旧的 `.key` / `.txt` 激活码 |
| `POST` | `/api/delete` | 从台账删除一条记录（不影响已签发授权码） |

### 16.5 环境变量

| 变量 | 作用 |
| --- | --- |
| `TUKU_LICENSE_PRIVATE_KEY` | 签发脚本 / 管理工具读取私钥（CI secret） |

| `TUKU_LICENSE_ADMIN_DATA` | 管理工具数据目录，默认仓库下 `licenses/` |

| `TUKU_STRICT_LICENSE` | 仅未打包环境：`1` = 关闭开发态自动 Pro，按正式授权规则跑测试 |

| `TUKU_SKIP_OBFUSCATE` | 设为 `1` / `true` / `on` 时 `dist:secure` 跳过混淆 |

### 16.7 扩展一项专业版能力
